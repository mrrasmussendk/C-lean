# Native package contract

This file pins what `spec.md` leaves open, so that the three native packages and the
core agree. Where it and `spec.md` differ, `spec.md` wins and this file is fixed.

## Command

Each package ships one executable, `gate-<language>`:

```
gate-<language> analyze --root <dir> --out <dir> --config <gate.yaml> --architecture <architecture.yaml> --today <YYYY-MM-DD>
```

- Analyzes every source file of its language under `--root`.
- Writes `findings.sarif`, `graph.json` and `units.json` to `--out`.
- Exit 0 when the analysis ran, whatever it found. Exit 2 when the package itself
  failed or the inputs are malformed. Nothing else.
- Reads the clock nowhere: `--today` is the only date it knows (used by HD01).
- `gate-<language> --version` prints `<package version> spec <spec version>`.

## Files and classification

- Paths in every output are relative to `--root`, with forward slashes.
- **Test code**: a file matching `paths.tests` in `gate.yaml`. **Generated code**: a
  file matching `paths.generated`, or carrying the language's generated-code marker
  in its first five lines (`<auto-generated`, `@generated`). Generated files produce
  no findings, units or nodes.
- **Production code** is everything else. A rule applies to production code only
  unless its ID starts with `TS`, or the case says otherwise (HD01 and DC02 apply to
  tests too).
- **Component of a file**: the first component in `architecture.yaml` whose `paths`
  glob matches. Globs: `**` any number of directories, `*` within one segment.

## Findings (`findings.sarif`, SARIF 2.1.0)

One run; `tool.driver.name` is `gate-<language>`. Per result:

- `ruleId`: an ID from `spec/rules.yaml`.
- `level`: `error` for block, `warning` for warn, `note` for report, after applying
  `rules.<ID>.severity` from `gate.yaml`.
- `message.text`: `<ID>: <what is wrong, with measured value and limit>. <what to do>.`
- `locations[0].physicalLocation.artifactLocation.uri` and `.region.startLine`.
- `partialFingerprints["gate/v1"]`: `<ID>|<file>|<symbol ID>` when the finding is on
  a symbol, else `<ID>|<file>|<sha256 of the trimmed source line>`.
- A finding silenced by a valid suppression is still written, with
  `suppressions: [{"kind": "inSource"}]`.

**Finding line.** A finding on a function or type is on the line of its name (for an
anonymous function, the line it starts on). A finding on a parameter is on the
parameter's line. Any other finding is on the line of the offending construct.

**Limits** come from `rules.<ID>.limit` in `gate.yaml`, default from `spec/rules.yaml`.

## Suppression (HD01)

The only accepted form, in a comment on the finding's line or the line directly above:

```
gate:allow <RULE-ID> reason="<text>" expires=<YYYY-MM-DD> approver=<name>
```

It silences findings of that rule on that line. It is itself an HD01 violation when a
field is missing, the rule ID is unknown, `expires` is before `--today`, or it
silences nothing. A compiler or linter disable switch (`#pragma warning disable`,
`[SuppressMessage]`, `eslint-disable*`, `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`,
`# noqa`, `# type: ignore`, `# pyright: ignore`) is an HD01 violation.

## Symbol IDs

`<language>:<package>:<fully qualified name>(<parameter types>)`, parameter types
comma-separated without spaces, the parenthesised part only on functions.

- C#: package is the assembly name. `csharp:Shop.Core:Shop.Core.Orders.Total(System.Int32,System.String)`
- TypeScript: package is the `name` in the nearest `package.json`, else `-`; the name
  is the root-relative module path without extension, then the declaration path.
  `typescript:shop:src/orders.Orders.total(number,string)`
- Python: package is the top-level package or module name; the name is the dotted
  module path, then the qualified name. Unannotated parameters have type `?`.
  `python:shop:shop.orders.Orders.total(int,str)`
- Anonymous functions: the enclosing symbol's name, then `<lambda>` and the 1-based
  index in source order within that symbol: `...Orders.total.<lambda>1()`.

## Graph (`graph.json`)

Schema: `spec/schemas/graph.schema.json`.

- A node per type (`type`), per interface, protocol or abstract type (`abstraction`),
  and per function, defined under `--root`. Nothing for external symbols.
- Edges between those nodes only: `call`, `construct`, `inherit` (including
  implementing an abstraction), `type_reference` (parameter, return, field, generic
  argument, and source-level references such as `nameof`). No self edges. Each
  (from, to, kind) once. A `type_reference` is from the function, or from the type
  for a field.
- `effect` is true on a function that directly calls an effect API (see FX01).
- Nodes are sorted by `id`; edges by (`from`, `to`, `kind`).
- Python only: a call whose target cannot be resolved to a node or to an imported
  external symbol is a GR01 finding.

## Units (`units.json`)

Schema: `spec/schemas/units.schema.json`. One unit per function with a body.

- `sloc`: body lines that are neither blank nor comment-only. A documentation string
  that is the first statement of a Python body counts as a comment. A nested
  function's lines count toward the enclosing body as well.
- `callers`: distinct production functions under `--root` that call it.
- `sequences`: for each block in the body, each window of N consecutive statements,
  N = `DU01.limit` in production code and `TS03.limit` in test code. A block with
  fewer than N statements yields nothing. Declarations of nested functions are one
  statement.

## Normalized hash

Steps 1 to 6 in `spec.md`. The serialization is package-private (hashes are only
compared within one language) but must satisfy the hash suite:

- Equal: identifiers renamed consistently; a literal replaced by another of the same
  type; reformatted; comments changed.
- Different: an operator changed; a call's argument count changed; statements
  reordered; a literal's type changed; a declared type changed; a control structure
  changed.

Identifier placeholders are numbered by first occurrence within the hashed fragment.
Names of members accessed on something (`x.Name`), of called functions and of types
are identifiers too and get placeholders. Language keywords and operators are kept.

## Effect APIs (FX01)

Each package keeps one list, in one file, of the standard-library and runtime APIs
that are effects, grouped as clock, file system, network, console, randomness,
environment. An assignment to a mutable static or module-level variable from inside a
function is the seventh group, mutable global state. Constructing a time value from
literals is not a clock read.

## Rule code layout (self-hosting)

- One file per rule, named `<ID>.<ext>`, in one `rules` directory per package.
- The file opens with a comment: `<ID>: <definition sentence from spec/rules.yaml>`.
- One entry function per file, taking the analyzed unit, file or graph and returning
  findings. The body reads: measure, compare to the limit, build the message.
- No reflection, runtime code generation or dispatch by name; rules are registered
  in an explicit list. No shared mutable state. Only the package's reader and writer
  modules touch the file system.

## Corpus

- Neutral cases: `corpus/cases/<SUITE>.yaml`.
- Fixture for a case: `corpus/fixtures/<language>/<SUITE>/<case id>/`, holding the
  source files and `expected.yaml`. A fixture may hold its own `gate.yaml` or
  `architecture.yaml`; otherwise `corpus/defaults/` is used. `--today` is 2026-01-01.
- `expected.yaml` for a rule case: `findings: [{rule: SZ01, file: orders.py, line: 3}]`
  or `findings: []`. The harness compares the unsuppressed findings whose rule is in
  the case's `rules` (default: the case's own rule), as a set of (rule, file, line).
- Hash suite: the fixture defines functions named `left` and `right`;
  `expected.yaml` is `equal: true` or `equal: false`.
- Graph suite: `expected.yaml` holds `nodes` (id, kind, component) and `edges`
  (from, to, kind); the harness compares them exactly with the produced graph.
